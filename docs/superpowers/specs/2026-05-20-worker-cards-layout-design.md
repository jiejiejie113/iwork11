# 工人详情 — 版面2 卡片视图

## 目标

在现有详情表格（版面1）基础上新增卡片视图（版面2），两者通过 Tab 切换，共享同一数据源。

## 改动范围

仅 `iwork/templates/iwork/production_detail.html`。

## Tab 切换

详情页顶部新增 Tab 栏：

- **表格视图**（版面1）— 保留当前完整功能
- **卡片视图**（版面2）— 新增，无目标编辑

## 版面2 布局规格

### 工人排列

- 工人按 `reg_per_sys_id` 自然升序排列
- 每行 2 张卡片（`grid grid-cols-2`），居中对齐
- 奇数工人时最后一行右侧留空

### 卡片结构

```
┌──── 左卡 ──────────┐   ┌──── 右卡 ──────────┐
│ 工序70 120   ┌──┐  │   │  ┌──┐  工序70 90   │
│ 工序80 80    │XXXX│ │   │  │XXXX│  工序80 --  │
│ ✓111%       └──┘  │   │  └──┘   差60 60%  │
└───────────────────┘   └───────────────────┘
```

- **左卡**：数据在左（left-align），头像在卡片右边缘
- **右卡**：头像在卡片左边缘，数据在右（right-align）
- 两个头像彼此相对，中间无数据

### 头像方块

- 48px × 48px 实心方块，8px 圆角
- 内部显示工人 ID 后几位（数字）
- 颜色规则：

| 条件 | 颜色 | 额外显示 |
|------|------|----------|
| 未设目标（target=0） | `#3b82f6` 天蓝 | 无 |
| 达标（qty ≥ target） | `#22c55e` 绿色 | `✓ 效率%` |
| 不达标（qty < target） | `#ef4444` 红色 | `差X件` + `效率%` |

### 数据区

- 动态拉出该工人涉及的所有工序产量（来自 `emp.steps`）
- 格式：`工序{X} {qty}件`
- 无数据的工序不显示
- 底部状态行显示合计 + 达标情况

## 数据流

- 复用 `loadDetail()` → API 返回 `employees`
- `targets` 从 Redis/WebSocket 同步（版面1 编辑保存后，版面2 自动看到颜色变化）
- 版面2 不渲染编辑按钮/输入框

## 实现要点

| 项目 | 内容 |
|------|------|
| 新状态 | `detailLayout = ref('table')` — 'table' / 'cards' |
| 新计算属性 | 无（复用 `employees`, `filteredEmployees`, `detailStepnos`） |
| 工人排序 | 默认 `reg_per_sys_id` 自然升序 |
| 左右卡区分 | 根据工人在排序后的奇偶位置：偶数索引 → 左卡，奇数索引 → 右卡 |
| 颜色确定 | `getStatusColor(emp)` → 返回 'green'/'red'/'blue' |

## 拖拽排序 + 布局持久化

### 交互

- 卡片支持 HTML5 Drag & Drop 拖拽
- 拖动卡片到目标位置释放，重新排列顺序
- 拖动时卡片半透明，目标位置显示插入指示线
- 移动端支持 touch 事件（可选）

### localStorage 持久化

- 唯一键：`worker-card-order:{detailType}:{detailKey}`
  - 例：`worker-card-order:flow:SO2-L2A`
- 值：`[1001, 1003, 1002, 1005, 1004]` — 工人 ID 的有序数组
- 页面加载时优先读取 localStorage，无缓存则用默认排序
- 拖拽释放后自动保存新顺序

### 生命周期

```
页面加载 → 读 localStorage → 有缓存？→ 按缓存排序
                                     → 无缓存？→ 默认ID升序
拖拽释放 → 更新数组顺序 → 写 localStorage → 重渲染
切换 Flow/工序 → 重新读该 key 对应缓存
```
