# pytckreg3 导出工具 GUI 设计

## 目标

为 `scripts/export_pytckreg3.py` 构建一个 customtkinter 图形界面，供非技术人员使用，打包为独立 `.exe`。

## 核心原则

- **不改动** `export_pytckreg3.py` 中 `export_to_csv()` 和 `export_month_to_csv()` 的函数签名与内部逻辑
- GUI 仅负责收集参数、输入校验、线程调度、进度展示
- 脚本中 `MODE`、`TARGET_DATE` 等模块级变量不再使用，GUI 直接传参调用函数

## 布局

```
┌──────────────────────────────────────────────────┐
│  pytckreg3 数据导出工具                            │
├──────────────────────────────────────────────────┤
│  [按日期导出]  [按月份导出]                         │
├──────────────────────────────────────────────────┤
│   目标日期/月份:  [2026-06-26]  📅                 │
│   工序号筛选:     [           ]  (可选，逗号分隔)    │
├──────────────────────────────────────────────────┤
│   数据库:    [VCO (192.168.3.15)        ▼]        │
│   输出目录:  [C:\...\output           ] [浏览...]  │
├──────────────────────────────────────────────────┤
│   状态: 导出中...                                 │
│   ════════════════════  (循环滚动)                 │
│   已导出: 1,234,567 条                            │
├──────────────────────────────────────────────────┤
│              [ 开始导出 ]  [ 取消 ]                │
└──────────────────────────────────────────────────┘
```

- 窗口固定宽度约 550px
- 顶部 CTkTabview 切换两种导出模式
- 中部为当前模式的参数输入区
- 中下部为共享配置（数据库、输出目录）
- 下部为进度条和状态
- 底部为操作按钮

## 组件与参数映射

| 组件 | 映射参数 | 说明 |
|------|----------|------|
| 日期标签页 → 日期输入框 | `target_date` | 默认当天，格式 `YYYY-MM-DD`，纯文本输入 + 格式校验 |
| 日期标签页 → 工序号输入 | `stepno_filter` | 可选，逗号分隔如 `69,70`，解析为 `list[int]` |
| 月份标签页 → 月份/日期输入 | `target_month` | 支持 `YYYY-MM`（整月）或 `YYYY-MM-DD`（单日） |
| 月份标签页 → 工序号输入 | `stepno_filter` | 同上 |
| 数据库下拉框 | `IWORK_DB_HOST` | VCO (`192.168.3.15`) / EST (`192.168.4.19`) |
| 输出目录选择 | `output_dir` | 默认程序所在目录下的 `output/`，浏览按钮调用 `filedialog.askdirectory()` |

## 数据流

```
用户输入 → GUI 收集参数 → 构建 kwargs → 后台线程调用

  MODE=date → export_to_csv(
      target_date=date,
      output_dir=pathlib.Path,
      stepno_filter=list[int] | None
  )

  MODE=month → export_month_to_csv(
      target_month=str,
      stepno_filter=list[int],
      output_dir=pathlib.Path
  )
```

## 线程模型

- 导出在后台线程执行，避免阻塞 UI，确保取消按钮可用
- 点击"开始导出"后禁用输入控件，防止重复提交
- 脚本中 `logger.info("已写入 N 条")` 通过自定义 loguru sink 捕获，转为进度更新
- UI 通过 `after(100ms)` 轮询共享状态变量，更新进度条和行数标签
- "取消"按钮设置 `threading.Event`，后台线程在每次写入 chunk 后检查该事件，若被设置则关闭数据库连接并退出
- 取消后已写入的文件保留（部分数据）

## 交互细节

- **输入校验**：日期/月份格式错误时，开始按钮点击后弹出 `CTkToplevel` 消息框提示，不启动导出
- **导出完成**：弹窗显示文件路径和总行数
- **进度条**：流式导出无法预知总行数，使用 `indeterminate` 模式循环滚动，配合实时行数标签
- **错误处理**：数据库连接失败/查询失败时，状态标签红色显示错误信息，并弹窗提示
- **窗口关闭**：导出进行中关闭窗口时，弹出确认提示"正在导出，确定退出？"
