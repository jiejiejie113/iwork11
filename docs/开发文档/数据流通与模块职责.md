# 数据流通与模块职责

> 项目：iwork 生产看板系统 | 日期：2026-05-15

本文档梳理各个模块的职责，以及数据如何从数据库流向前端每个主题。

---

## 一、模块职责一览

| 模块           | 文件                                     | 职责                                                               |
| -------------- | ---------------------------------------- | ------------------------------------------------------------------ |
| 模型层（远程） | `iwork/models.py`                      | 映射远程 MySQL `payroll.pytckreg3` 表，`managed=False`，只读   |
| 模型层（本地） | `iwork/local_models.py`                | 映射本地 MySQL `iwork_local.pytckreg3` 表，同步目标              |
| 数据库路由     | `iwork/database_router.py`             | 根据 `app_label` 和 `model_name` 将读写路由到正确的数据库      |
| 查询层（远程） | `iwork/queries.py`                     | 封装所有远程数据库的聚合查询，每个函数返回特定维度的统计结果       |
| 查询层（本地） | `iwork/local_queries.py`               | 镜像 `queries.py`，查询本地同步库                                |
| 统计调度       | `iwork/statistics.py`                  | **中央枢纽**：调用全部查询函数，组装统一的 stats dict        |
| 实时 API       | `iwork/api_views.py`                   | HTTP 端点，接收前端请求并返回统计数据                              |
| 历史 API       | `iwork/api_views_local.py`             | 历史数据 HTTP 端点 + 数据同步接口                                  |
| URL 路由       | `iwork/urls.py` / `history_urls.py`  | 将 URL 映射到视图函数                                              |
| Celery 任务    | `iwork/tasks.py`                       | 定时 60s 刷新缓存并写入 Redis（SSE 数据源）                    |
| SSE 推送       | `iwork/api_views.py` → `dashboard_stream` | 从 Redis 读取缓存，每 60s 通过 SSE 推送 `dashboard_update` 到浏览器 |
| 页面视图       | `iwork/views.py`                       | 渲染 `dashboard.html` 模板，注入初始 `page_title` 和 `stats` |
| 前端（实时）   | `iwork/templates/iwork/dashboard.html` | Vue 3 单页应用，Chart.js 渲染 7 大主题，EventSource 接收 SSE 推送 |
| 前端（详情）   | `iwork/templates/iwork/production_detail.html` | Vue 3 单页应用，Flow/StepNo 两级钻取，员工目标产量设置     |
| 数据同步       | `iwork/sync.py`                        | 远程 → 本地的日数据同步，含变更检测                               |

## 二、4 条数据流通路径

### 路径 A：SSE 自动推送（Batch 引擎，每 60 秒触发）

```
Celery Beat 定时调度器（celery.py，每 60 秒触发一次）
    │
    ▼
tasks.sync_dashboard_stats()          # Celery 异步任务入口
    │
    ▼
statistics.get_batch_stats()          # Batch 批量引擎：一次查询覆盖全部工序
    │
    ├──▶ get_batch_basic_stats()      ──▶ 每个 StepNo 的 SUM(Qty)              → KPI
    ├──▶ get_batch_hourly_stats()     ──▶ 每个 StepNo 的 HOUR, SUM(Qty)        → 趋势
    ├──▶ get_batch_process_by_flow()  ──▶ 每个 StepNo 的 StepNo, Flow, SUM     → 工序×Flow
    ├──▶ get_batch_heatmap_matrix()     ──▶ 每个 StepNo 的 HOUR, Flow, SUM       → 热力图
    ├──▶ get_batch_station_ranking()  ──▶ 每个 StepNo 的 StationID, SUM        → 工站
    ├──▶ get_batch_workorders_list()  ──▶ 每个 StepNo 的 WrkOrder, SUM, COUNT  → 工单
    ├──▶ get_batch_monthly_total_trend() → 每个 StepNo 的 DATE, SUM            → 月趋势
    └──▶ get_batch_monthly_process_stats()→ 每个 StepNo 的 DATE, StepNo, SUM   → 月堆积
              │  ↑ 月趋势缓存跨天保留（30 天 TTL），每日增量追加
              ▼
    ┌─────────────────────────────┐
    │  Pytckreg3.objects          │
    │  .using('iwork')            │
    │  MySQL 远程库 payroll        │
    └─────────────────────────────┘
              │
              ▼
    batch = {70: {...}, 69: {...}, ..., 'all': {...}}
              │  约 90 个工序，每个包含全部 12 个图表字段
              ▼
statistics.cache_batch_to_redis(batch)
    │  为每个工序写独立 key: stats:realtime:70, stats:realtime:69, ...
    │  TTL = 到今晚 24:00 的秒数（午夜自动过期）
    │  同时写 stats:realtime:all（全工序合并）
    ▼
Redis 缓存层
    │
    ├── HTTP 路径 B 直接读取（<1ms，无需查 DB）
    │
    └── SSE 推送：
          │  取 batch[70]（成衣工序默认视图）
          ▼
        /api/dashboard/stream/ 端点 → 从 Redis 读取 → SSE text/event-stream
          │
          ▼
        浏览器 EventSource.onmessage → JSON → 浏览器
          │
          ▼
        Vue: Object.assign(data, msg.data) → renderAllCharts()

性能说明：
  - 8 次批量查询（GROUP BY StepNo），每条返回 90× 的数据 → 仍 <5s
  - Celery 一次性算完所有工序，HTTP 纯读缓存 → 响应 <1ms
  - 月趋势缓存跨天保留（30 天），每日仅追加当天数据
  - 午夜自动过期：第二天 Celery 自动重建新一天的全量缓存
```

### 路径 B：实时 HTTP 请求（纯读缓存，<1ms）

```
浏览器（Vue 前端）
  loadRealtimeData()
  → fetch('/api/dashboard/realtime/?stepno=70')
      │
      ▼
Django URL 路由（urls.py）
  path("api/dashboard/realtime/", realtime_stats)
      │
      ▼
api_views.realtime_stats(request)
      │
      ▼
api_views._parse_stepno(request) → [70]
      │
      ▼
statistics.get_realtime_stats(stepno_filter=[70])
      │
      ├── cache.get('stats:realtime:70') → 命中 ✅  <1ms
      │     Celery 路径 A 已提前算好所有工序，HTTP 不查 DB
      │
      └── 缓存未命中（冷启动 / 极端情况）
            │  自定义组合（如 stepno=70,69）：从 batch 缓存合并
            │  单个工序：回退到 _get_date_stats 实时查询 → 写入缓存
            ▼
            stats dict → JSON → 浏览器 → renderAllCharts()

与路径 A 的关系：
  - 路径 A（Celery）是唯一的生产者，每 60s 批量构建所有工序
  - 路径 B（HTTP）是纯粹的消费者，只从 Redis 读取
  - 不再存在缓存键不一致的问题（改为统一的 stats:realtime:* 命名）
```

### 路径 C：历史 HTTP 请求（用户访问独立历史页面 /history/）

```
浏览器（Vue 前端）
  用户访问 /history/ → Django 注入 initial_view='history'
  onMounted: 不连 WebSocket → loadAvailableDates() → loadHistoryData()
      │
      ▼
fetch('/api/history/date/2026-04-24/?mode=local&stepno=70')
      │                      │            │
      │                      │            └── stepno=70: 工序过滤
      │                      └── mode=local: 查本地库 / mode=remote: 查远程库
      │
      ▼
Django URL 路由（history_urls.py）
  path("date/<str:target_date>/", local_date_stats)
      │
      ▼
api_views_local.local_date_stats(request, target_date='2026-04-24')
      │
      ├── mode == 'local'
      │     └──▶ statistics.get_local_date_stats(date_obj, stepno_filter)
      │            → _get_date_stats(date_obj, [70], local_q)
      │              │  与实时视图完全相同的 2 阶段并行引擎
      │              │  只是: target_date=指定日期, q=local_queries
      │              ▼
      │           LocalPytckreg3.objects.using('iwork_local')
      │           MySQL 本地库 iwork_local
      │
      └── mode == 'remote'
            └──▶ statistics.get_date_stats(date_obj, stepno_filter)
                   │  先查 Redis: stats:date:{date}:{stepno} → 命中直接返回
                   │  未命中 → _get_date_stats(date_obj, [70], remote_q)
                   │     │  2 阶段并行引擎
                   │     ▼
                   │  Pytckreg3.objects.using('iwork') → MySQL 远程库
                   │     │
                   │     ▼
                   │  stats dict → 写入缓存(TTL 30min) → 返回
                   ▼
                  JSON → 浏览器
      │
      ▼
    JSON Response → 浏览器（字段结构与实时视图完全一致）
      {
        date, source,
        total_qty, workorder_count,           // KPI
        hourly_stats,                         // 每小时趋势
        process_flow_stats,                   // 工序×Flow
        monthly_process_stats,                // 月工序堆积
        monthly_total_trend,                  // 月趋势
        station_stats,                        // 工站分布
        heatmap_matrix,                         // 热力图
        station_ranking,                      // 工站排行
        workorders                            // 工单列表
      }
      │
      ▼
Vue: Object.assign(data, ...) → renderAllCharts()
  历史视图现在拥有与实时视图完全一致的 12 个图表数据字段

================================================================================
关键变化（v2）：
  - 历史视图使用独立的 URL /history/（不连接 WebSocket）
  - mode=local 和 mode=remote 均使用统一的 _get_date_stats 并行引擎
  - mode=remote 不再只返回 2 个 KPI，而是返回全部 12 个图表字段
  - 实时、历史-local、历史-remote 三条路径共用同一套并行查询逻辑
```

### 路径 D：生产详情 HTTP 请求（Business Detail，独立 URL）

```
浏览器（Vue 前端）
  用户访问 /production/detail-data/ → Django 注入 initial_view='overview'
  onMounted: connectWS() → loadOverview()
      │
      ▼
fetch('/api/dashboard/detail/flows/?date=2026-05-14')
      │
      ▼
api_views.flow_overview(request)
      │
      ├── 今日(默认)
      │     └──▶ cache.get('stats:detail:flow_overview')  → 命中 ✅ <1ms
      │           未命中 → remote_get_batch_flow_overview → 写入缓存(TTL 到午夜)
      │
      └── 历史(?date=2026-04-24&mode=local)
            └──▶ local_get_batch_flow_overview → 查本地库

  用户点击 Flow 卡片 → /production/detail-data/flow/VCO-L5/
      │
      ▼
fetch('/api/dashboard/detail/flow/VCO-L5/?date=...')
      │
      ▼
api_views.flow_detail(request, flow_name='VCO-L5')
      │
      ├── 今日
      │     └──▶ cache.get('stats:detail:flow:VCO-L5') → 命中 ✅
      │           未命中 → _get_flow_detail_data() → remote_get_batch_flow_employees + hourly
      │
      └── 历史 → _get_flow_detail_data(mode='local') → local_get_batch_flow_employees

  员工表格输入目标 → 点击"全部保存"
      │
      ▼
fetch POST /api/dashboard/set-targets/ { body: { targets: {1001: 100} } }
      │
      ▼
api_views.set_targets() → 写入 Redis + 数据库双写
      │
      ├── Redis SET targets:{date}:{flow} = JSON({1001: 100})
      └── 数据库 target_production 表持久化
            │
            ▼
          所有在线客户端通过 SSE 收到更新
```

**关键变化（v4）：**
- 新增独立 URL /production/detail-data/ 及 Flow/StepNo 详情子路由
- Celery 每 60s 并行构建 Flow/StepNo 员工明细（get_batch_detail_stats）
- 详情 API 读 Redis（对齐路径 A/B 模式），<1ms 响应
- 目标产量通过 HTTP POST 设置 + SSE 推送确认（替代原 WebSocket 双向通信）
- 目标产量双写：Redis 缓存 + 数据库 `target_production` 表持久化，TTL 到午夜

### 4.2 statistics.py — 两层架构（Batch 引擎 + 历史引擎）

```python
# ====== Batch 批量引擎（Celery 使用，一次构建全部工序） ======

get_batch_stats(q=None) -> dict
  # 返回 {70: stats_dict, 69: stats_dict, ..., 'all': stats_dict}
  # 6 个 batch 查询并行 + 月趋势增量追加 + 按 stepno 组装

cache_batch_to_redis(batch) -> None
  # 为每个工序写独立缓存键: stats:realtime:70, stats:realtime:69, ...
  # TTL = 到今晚 24:00 的秒数

# ====== Batch 详情引擎（Celery 使用，一次构建全部 Flow/StepNo 明细） ======

get_batch_detail_stats(q=None) -> dict
  # 返回 {flow_overview, flow_hourly, flow_employees}
  # 3 个 batch 查询并行（ThreadPoolExecutor(3)）
  # q=None → 使用 remote_q，可传入 local_q

cache_detail_batch_to_redis(detail_batch) -> None
  # 写入缓存键: stats:detail:flow_overview, stats:detail:flow_hourly,
  #   stats:detail:flow:<name>（每个 Flow 独立键）
  # TTL = 到今晚 24:00 的秒数

# ====== 公共入口 ======

# 实时视图：纯读 Redis 缓存（不查 DB）
get_realtime_stats(stepno_filter=None) -> dict
  # cache.get('stats:realtime:70') → 命中 <1ms
  # 未命中 → 回退到 _get_date_stats 实时查询

# 历史视图（远程）：查远程库，结果缓存 30 分钟
get_date_stats(target_date, stepno_filter=None) -> dict
  # cache.get('stats:date:{date}:{stepno}') → 命中直接返回
  # 未命中 → _get_date_stats → 写入缓存(TTL 1800s)

# 历史视图（本地）：查本地库，结果缓存 1 小时
get_local_date_stats(target_date, stepno_filter=None) -> dict
  # cache.get('stats:local:date:{date}:{stepno}') → 命中直接返回
  # 未命中 → _get_date_stats(local_q) → 写入缓存(TTL 3600s)

# 同步后清缓存
invalidate_local_cache(target_date) -> None
  # sync_date_data() 完成后调用，删除本地历史缓存

# 今日数据（保留兼容）
get_today_stats(stepno_filter=None) -> dict
  # → get_date_stats(today, stepno_filter)

# ====== 内部引擎 ======

# 单工序查询引擎（历史查询 + batch 回退使用）
_get_date_stats(target_date, stepno_filter, q_mod) -> dict
  # q_mod = remote_q / local_q
  # 2 阶段并行，8 次查询

# 工序缓存键后缀
_stepno_key(stepno) -> str   # None→'all', [70]→'70', [70,69]→'69_70'

# TTL 计算
_seconds_to_midnight() -> int  # 距离今晚 24:00 的剩余秒数
```

**Batch 引擎执行流程：**

```
get_batch_stats():
  第 1 阶段（6 线程并行）
    ├── get_batch_basic_stats()        → {70: {total_qty}, 69: {...}, ...}
    ├── get_batch_hourly_stats()       → {70: [{hour,qty}], ...}
    ├── get_batch_process_by_flow()    → {70: [{step,flow,qty}], ...}
    ├── get_batch_heatmap_matrix()       → {70: {hours,flows,data}, ...}
    ├── get_batch_station_ranking()    → {70: [{station,qty}], ...}
    └── get_batch_workorders_list()    → {70: [{wrk_order,...}], ...}
  第 2 阶段：月趋势（增量追加）
    ├── Redis 读取历史月数据 → 追加今天 → 写回
  第 3 阶段：按 stepno 组装
    └── 每个工序独立组装完整 stats dict + 'all' 合并视图
```

**缓存键命名规范：**

| 路径               | 缓存键格式                                               | TTL          |
| ------------------ | -------------------------------------------------------- | ------------ |
| 实时（batch 批量） | `stats:realtime:{stepno}`                              | 到今晚 24:00 |
| 实时工序列表       | `stats:realtime:_process_list`                         | 到今晚 24:00 |
| 历史（远程）       | `stats:date:{date}:{stepno}`                           | 1800s        |

## 五、`stepno_filter` 的完整穿透路径

从用户点击工序选择器到 SQL 执行的完整追踪：

```
┌── 前端（Vue 3） ──────────────────────────────────────────┐
│                                                             │
│  用户点击工具栏 "工序: 70" 下拉 → 选择 70                     │
│      │                                                      │
│      ▼                                                      │
│  stepnoFilter = [70]           # Vue 响应式状态               │
│      │                                                      │
│      ▼                                                      │
│  buildStepnoParam()            # 构建查询参数                 │
│    stepnoFilter.length > 0 ? `stepno=${stepnoFilter.join(',')}` : '' │
│    → "stepno=70"                                            │
│      │                                                      │
│      ▼                                                      │
│  loadRealtimeData()            # 触发数据刷新                 │
│    fetch(`/api/dashboard/realtime/?stepno=70`)              │
│                                                             │
└──────────────────────┬──────────────────────────────────────┘
                       │ HTTP GET 请求
                       ▼
┌── Django 后端 ──────────────────────────────────────────────┐
│                                                             │
│  urls.py 路由匹配                                           │
│    path("api/dashboard/realtime/", realtime_stats)          │
│      │                                                      │
│      ▼                                                      │
│  api_views.realtime_stats(request)                          │
│      │                                                      │
│      ▼                                                      │
│  api_views._parse_stepno(request)  # 解析查询参数            │
│    raw = request.query_params.get('stepno', '')             │
│    空字符串 → None  (全工序，不加过滤)                        │
│    "70"     → [70]  (单工序)                                 │
│    "70,69"  → [70, 69]  (多工序，逗号分隔)                    │
│    "abc"    → []  (非法值，忽略)                              │
│      │                                                      │
│      ▼                                                      │
│  statistics.get_realtime_stats(stepno_filter=[70])          │
│      │                                                      │
│      ▼                                                      │
│  statistics.get_today_stats(stepno_filter=[70])             │
│      │                                                      │
│      ├──▶ get_basic_stats(target, stepno_filter=[70])       │
│      ├──▶ get_hourly_stats(target, stepno_filter=[70])      │
│      ├──▶ get_process_stats(target, stepno_filter=[70])     │
│      ├──▶ get_station_stats(target, stepno_filter=[70])     │
│      ├──▶ get_heatmap_matrix(target, stepno_filter=[70])      │
│      ├──▶ get_station_ranking(target, stepno_filter=[70])   │
│      ├──▶ get_workorders_list(target, stepno_filter=[70])   │
│      └──▶ get_monthly_total_trend(start, end, [70])         │
│            (每个查询函数都接收并透传 stepno_filter)            │
│              │                                              │
│              ▼                                              │
│  queries.py: apply_stepno_filter(queryset, [70])            │
│    # 核心过滤逻辑（所有查询函数共用此工具函数）                │
│    def apply_stepno_filter(queryset, stepno_filter):         │
│        if stepno_filter:                                    │
│            return queryset.filter(StepNo__in=stepno_filter) │
│        return queryset  # None 时原样返回，不过滤              │
│      │                                                      │
│      ▼                                                      │
│  Django ORM → SQL:                                          │
│    SELECT TicketNo, WrkOrder, StepNo, Qty, ...              │
│    FROM pytckreg3                                           │
│    WHERE RegDate >= '2026-05-09 00:00:00'                   │
│      AND RegDate <  '2026-05-10 00:00:00'                   │
│      AND StepNo IN (70)        ← 由 stepno_filter 控制      │
│                                                             │
│  全工序模式（stepno_filter=None）：                           │
│    WHERE RegDate >= '2026-05-09 00:00:00'                   │
│      AND RegDate <  '2026-05-10 00:00:00'                   │
│      -- 无 StepNo 过滤，返回所有工序数据                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
                       │
                       ▼
              MySQL 远程库 payroll.pytckreg3
              RegDate 索引加速日期范围查询
                       │
                       ▼
              结果集 → ORM 映射 → stats dict → JSON → 浏览器
```

关键设计：

- `stepno_filter=None` 和 `stepno_filter=[]` 语义不同：前者是全工序（不加过滤），后者表示"没有匹配的工序"（理论上不应出现）
- `apply_stepno_filter` 是唯一的过滤入口，所有查询函数复用同一逻辑，避免 SQL 注入和不一致
- 过滤逻辑在 **数据库层面** 完成（`WHERE StepNo IN (...)`），而非 Python 层面，充分利用数据库索引

## 六、数据库路由规则

`DatabaseRouter` 是 Django 多数据库架构的核心，通过 `app_label` 和 `model_name` 决定每次查询走哪个库。

```
DatabaseRouter（iwork/database_router.py）

  db_for_read(model):     ← 读操作路由（SELECT）
    │
    ├── model._meta.app_label == 'iwork'
    │     ──▶ 'iwork'（远程生产库）
    │         所有 models.py 中 app_label='iwork' 的模型的读操作
    │         都走远程库 payroll.pytckreg3
    │
    ├── model._meta.model_name == 'localpytckreg3'
    │     ──▶ 'iwork_local'（本地镜像库）
    │         LocalPytckreg3 模型的读操作走本地库
    │
    └── 其他所有模型
          ──▶ 'default'（Django 系统库）
              auth、sessions、django_celery_beat 等系统表

  db_for_write(model):    ← 写操作路由（INSERT/UPDATE/DELETE）
    │
    ├── app_label == 'iwork'
    │     ──▶ None（禁止写入！）
    │         远程生产库 payroll 是只读的，
    │         任何对 Pytckreg3 的写操作都会被拒绝
    │
    ├── model_name == 'localpytckreg3'
    │     ──▶ 'iwork_local'（本地镜像库）
    │         同步数据写入本地库
    │
    └── 其他
          ──▶ 'default'

  allow_migrate(db, app_label):  ← 迁移控制（migrate 命令）
    │
    ├── app_label == 'iwork'
    │     ──▶ False（禁止迁移）
    │         models.py 中 managed=False，
    │         加上这里返回 False，双重保证不会对远程表执行 DDL
    │
    └── 其他
          ──▶ db == 'default'（仅允许在 default 库上迁移）
```

三层数据库的物理分布：

```
┌──────────────────────┐  ┌────────────────────────┐  ┌──────────────────────┐
│  default（本地）       │  │  iwork（远程 192.168.x） │  │  iwork_local（本地）   │
│  ─────────────────── │  │  ────────────────────  │  │  ─────────────────── │
│  Django 系统表        │  │  payroll.pytckreg3     │  │  pytckreg3（同步副本） │
│  - auth_user         │  │  生产打卡数据（只读）    │  │  本地镜像（读写）      │
│  - django_session    │  │  ~3900 万行            │  │  结构与远程一致        │
│  - django_celery_beat│  │  RegDate 有索引         │  │  RegDate 有索引       │
│                      │  │                        │  │                      │
│  读写均可             │  │  读取：✅  写入：❌      │  │  读写均可             │
└──────────────────────┘  └────────────────────────┘  └──────────────────────┘
```
