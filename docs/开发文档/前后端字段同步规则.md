# 前后端字段同步规则

> 修改历史 API 返回字段或前端数据读取逻辑时，必须先读本文档。

---

## 耦合链路

```
api_views_local.local_date_stats()
  → statistics.get_date_stats() / get_local_date_stats()
    → _get_date_stats() 统一引擎
      → 返回 12 个字段的 dict
        │
        ▼
  Response JSON 字段：
    total_qty, workorder_count, date,
    hourly_stats, station_stats, workorders,
    process_flow_stats, monthly_process_stats,
    monthly_total_trend, heatmap_matrix, station_ranking,
    process_stats, top_processes
        │
        ▼
  dashboard.html loadHistoryData()：
    Object.assign(data, {
        total_qty:          result.total_qty           || 0,
        workorder_count:    result.workorder_count     || 0,
        hourly_stats:       result.hourly_stats        || [],
        station_stats:      result.station_stats       || [],
        workorders:         result.workorders          || [],
        process_flow_stats:  result.process_flow_stats  || [],  ← 不要硬编码为 []
        monthly_process_stats: result.monthly_process_stats || [],
        monthly_total_trend:   result.monthly_total_trend   || [],
        heatmap_matrix:          result.heatmap_matrix          || null,
        station_ranking:       result.station_ranking       || [],
        top_processes:         result.process_stats         || [],
    })
```

| API 字段 (`api_views_local.py`) | 前端取值 (`dashboard.html` loadHistoryData) | 前端用途 | 可为空 |

| `total_qty` | `result.total_qty \|\| 0` | KPI 卡片 | 否 |

| `station_stats` | `result.station_stats \|\| []` | 主题4 工站分布 | 否 |
| `workorders` | `result.workorders \|\| []` | 主题7 工单列表 | 否 |
| `process_flow_stats` | `result.process_flow_stats \|\| []` | 主题3a 工序×Flow | 是 |

## 修改规则

1. **在 `_get_date_stats()` 或 `local_date_stats()` 的 Response 中新增字段** → 必须在 `dashboard.html` 的 `loadHistoryData()` 中添加对应的 `result.xxx || default` 行
2. **删除字段** → 两边同步删除，同时在 `chart_fields` 验证列表中删除
3. **重命名字段** → 两边同步改名
4. **API 返回的字段与前端 `data` 对象的字段名必须一致**（`Object.assign` 按 key 匹配）
5. **测试要求**：修改后运行 `test_unified_engine.py::TestHistoryAPIResponse` 验证响应结构

---

## 容易出错的场景

| 场景 | 错误做法 | 正确做法 |
|------|---------|---------|
| API 新增字段 | 只改 `api_views_local.py`，漏掉前端 | 同步更新 `loadHistoryData()` |
| 前端"图表无数据" | 怀疑后端查询有问题 | 先检查 `loadHistoryData()` 是否硬编码为空 |
| 实时视图正常、历史视图异常 | 怀疑数据库问题 | 先对比实时/历史的 `data` 赋值逻辑差异 |
