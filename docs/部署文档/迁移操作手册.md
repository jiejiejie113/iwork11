## 2. 旧服务器操作

### 2.1 导出 Django 系统库

在旧服务器上执行，将 Django 认证和系统表导出为 SQL 文件：

```powershell
# 定位旧 MySQL 的连接信息
# 使用 mysqldump 导出 iwork_system 库
mysqldump -h localhost -u root -p `
  --routines --triggers --single-transaction `
  --default-character-set=utf8mb4 `
  iwork_system > system_db_dump.sql

# 确认导出成功
dir system_db_dump.sql
# 文件大小应 > 0
```

### 2.2 备份项目（保险）

```powershell
# 整个项目目录打包备份
Compress-Archive -Path "D:\DM\Python代码\Seamus\iwork" -DestinationPath "D:\iwork_backup_20260529.zip"
```

### 2.3 确认 .env 变更项

检查旧 `.env`，标记哪些值需要在新服务器上变更：

```
DJANGO_SECRET_KEY    → 不变或重新生成
DJANGO_DEBUG         → False（生产环境）
DJANGO_ALLOWED_HOSTS → 添加新服务器IP/域名

ACCESS_DB_*  → localhost（Docker MySQL）
IWORK_DB_*   → 保持不变（还是远程 192.168.3.15）
LOCAL_DB_*   → localhost（Docker MySQL）
```

## 4. 项目代码部署

### 4.1 克隆代码

```powershell
# 进入目标目录
cd D:\
mkdir iwork
cd iwork

# 克隆项目
git clone <仓库地址> .

# 或用 ZIP 解压
# Expand-Archive -Path "D:\iwork.zip" -DestinationPath "D:\iwork"
```

### 4.2 创建 .env 文件

```powershell
copy iwork\.env.example iwork\.env
notepad iwork\.env
```

按实际环境修改：

```ini
# Django 配置
DJANGO_SECRET_KEY=<新生成的安全密钥>
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,<服务器IP>,<域名>

# Django 系统数据库（Docker MySQL）
ACCESS_DB_HOST=127.0.0.1
ACCESS_DB_PORT=3306
ACCESS_DB_NAME=iwork_system
ACCESS_DB_USER=iwork_admin
ACCESS_DB_PASSWORD=<应用数据库密码>

# 远程业务数据库（不变）
IWORK_DB_HOST=192.168.3.15
IWORK_DB_PORT=3306
IWORK_DB_NAME=payroll
IWORK_DB_USER=iwork_readonly
IWORK_DB_PASSWORD=<远程库只读密码>

# 本地业务数据库（Docker MySQL）
LOCAL_DB_HOST=127.0.0.1
LOCAL_DB_PORT=3306
LOCAL_DB_NAME=iwork_local
LOCAL_DB_USER=iwork_admin
LOCAL_DB_PASSWORD=<与 ACCESS_DB_PASSWORD 相同>
```

### 4.3 创建 mysql-init 初始化脚本

新建文件 `mysql-init/01-create-databases.sql`：

```sql
CREATE DATABASE IF NOT EXISTS iwork_system
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE DATABASE IF NOT EXISTS iwork_local
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'iwork_admin'@'%'
  IDENTIFIED BY '<应用数据库密码>';

GRANT ALL PRIVILEGES ON iwork_system.* TO 'iwork_admin'@'%';
GRANT ALL PRIVILEGES ON iwork_local.* TO 'iwork_admin'@'%';
FLUSH PRIVILEGES;
```

## 6. 数据库迁移

### 6.1 导入系统库数据

将旧服务器导出的 `system_db_dump.sql` 拷贝到新服务器后：

```powershell
# 导入系统库
Get-Content system_db_dump.sql | docker exec -i mysql-iwork mysql -u root -p<root密码> iwork_system

# 或通过 TCP
mysql -h 127.0.0.1 -P 3306 -u root -p iwork_system < system_db_dump.sql
```

### 6.2 创建本地业务库表结构

```powershell
# 使用已有脚本创建 pytckreg3 表
python scripts/create_local_db.py
```

此操作创建：
- `iwork_local` 数据库（如不存在）
- `pytckreg3` 表（含主键和索引）

## 7. 首次部署执行

### 7.1 运行部署脚本

```powershell
# 在项目根目录执行
.\deploy.ps1
```

脚本会自动完成：

1. 环境检查（Docker、Python）
2. 确认 Docker 中间件已启动
3. 创建 Python 虚拟环境
4. 安装 pip 依赖
5. 执行 Django migrate（系统表）
6. 收集静态文件
7. 创建管理员账户（交互式）
8. 注册 Windows 服务
9. 启动所有服务

### 7.2 创建管理员账户

如果首次部署后没有管理员账户，需要手动创建：

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

按提示输入用户名、邮箱、密码。

### 7.3 验证服务状态

```powershell
.\deploy.ps1 -Status
```

期望输出：

```
Docker 容器:  redis-iwork Up, mysql-iwork Up
Windows 服务: iwork-daphne Running, iwork-celery-worker Running, iwork-celery-beat Running
```

## 8. Nginx 配置

### 8.1 安装配置

将项目中的 `iwork.conf` 复制到 Nginx 配置目录：

```powershell
copy iwork.conf <nginx安装目录>\conf\conf.d\iwork.conf
```

### 8.2 修改配置中的值

编辑 `iwork.conf`，替换以下占位符：

| 占位符 | 替换为 |
|--------|--------|
| `your-domain.com` | 实际服务器域名或 IP |
| `D:/iwork/staticfiles/` | 实际项目路径下的 staticfiles 目录 |

### 8.3 重载 Nginx

```powershell
nginx -s reload
```

### 8.4 接口路由表

| Nginx 路径 | 上游 | 说明 |
|------------|------|------|
| `/static/*` | 本地文件 | Nginx 直接返回，不代理 |
| `/ws/*` | Daphne :8000 | WebSocket 升级转发 |
| `/*` | Daphne :8000 | 通用 HTTP 代理 |

## 10. 日常运维

### 10.1 服务管理

```powershell
# 查看所有服务状态
.\deploy.ps1 -Status

# 重启所有服务
.\restart_services.ps1

# 停止所有服务
.\stop_services.ps1

# 启动所有服务（停止后重新启动）
Start-Service -Name "iwork-daphne"
Start-Service -Name "iwork-celery-worker"
Start-Service -Name "iwork-celery-beat"
```

### 10.2 升级更新

```powershell
# 拉取最新代码
git pull origin main

# 执行升级部署
.\deploy.ps1 -Upgrade
```

### 10.3 日志查看

```powershell
# 查看综合日志（实时滚动）
Get-Content logs\all_$(Get-Date -Format 'yyyy-MM-dd').log -Tail 50 -Wait

# 查看错误日志
Get-Content logs\error_$(Get-Date -Format 'yyyy-MM-dd').log -Tail 30

# 查看特定组件日志
Get-Content logs\daphne_stdout.log -Tail 30
Get-Content logs\celery_worker_stdout.log -Tail 30
Get-Content logs\celery_beat_stdout.log -Tail 30
```

### 10.4 Docker 维护

```powershell
# 查看容器日志
docker compose logs --tail=100

# 重启中间件
docker compose restart

# 停止中间件（不影响数据卷）
docker compose down

# 启动中间件
docker compose up -d

# 进入 MySQL 容器
docker exec -it mysql-iwork mysql -u root -p
```

### 10.5 日志清理

```powershell
# 清理 30 天前的普通日志
Get-ChildItem logs\all_*.log | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-30) } | Remove-Item

# 清理 30 天前的服务日志
Get-ChildItem logs\*_stdout.log, logs\*_stderr.log | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-30) } | Remove-Item
```

## 11. 故障排查

### 11.1 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| Daphne 服务启动失败 | 端口 8000 被占用 | `netstat -ano \| findstr 8000` 查看占用进程 |
| Celery Worker 无法启动 | Redis 未就绪 | 确认 `docker compose ps` 中 Redis 为 Up |
| API 返回空数据 | 远程库连接失败 | `Test-NetConnection 192.168.3.15 -Port 3306` |
| WebSocket 连接失败 | Nginx 未配置升级 | 检查 `iwork.conf` 中 `/ws/` location 配置 |
| 看板无实时更新 | Celery Beat 未运行 | `Get-Service iwork-celery-beat` |
| 静态文件 404 | collectstatic 未执行 | `python manage.py collectstatic --noinput` |
| 数据库连接拒绝 | MySQL 容器未启动 | `docker compose ps` 确认状态 |

### 11.2 查看错误详情

```powershell
# Windows 事件日志
Get-EventLog -LogName Application -Source "iwork-daphne" -Newest 10

# 各组件错误日志
Get-Content logs\daphne_stderr.log -Tail 20
Get-Content logs\celery_worker_stderr.log -Tail 20
Get-Content logs\celery_beat_stderr.log -Tail 20

# Django 配置检查
.\.venv\Scripts\python.exe manage.py check --deploy
```

### 11.3 完全重装

如需完全重新部署：

```powershell
# 1. 卸载服务
.\uninstall_services.ps1

# 2. 删除 Docker 容器和卷（这会丢失数据！）
docker compose down -v

# 3. 删除虚拟环境
Remove-Item -Recurse -Force .venv

# 4. 重新部署
.\deploy.ps1

# 5. 重新导入数据库
# 按第 6 节步骤操作
```
