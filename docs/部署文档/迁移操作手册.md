## 2. 旧服务器操作

### 2.1 导出 Django 系统库

在旧服务器上执行，将 Django 认证和系统表导出为 SQL 文件：

```powershell
# 定位旧 MySQL 的连接信息
# 使用 mysqldump 导出 iwork_system 库
mysqldump -h localhost -u root -p `
  --routines --triggers --single-transaction `
  --default-character-set=utf8mb4 `
  iwork_system > system_db_dump.sql

# 确认导出成功
dir system_db_dump.sql
# 文件大小应 > 0
```

### 2.2 备份项目（保险）

```powershell
# 整个项目目录打包备份
Compress-Archive -Path "D:\DM\Python代码\Seamus\iwork" -DestinationPath "D:\iwork_backup_20260529.zip"
```

### 2.3 确认 .env 变更项

检查旧 `.env`，标记哪些值需要在新服务器上变更：

```
DJANGO_SECRET_KEY    → 不变或重新生成
DJANGO_DEBUG         → False（生产环境）
DJANGO_ALLOWED_HOSTS → 添加新服务器IP/域名

ACCESS_DB_*  → localhost（Docker MySQL）
IWORK_DB_*   → 保持不变（还是远程 192.168.3.15）
LOCAL_DB_*   → localhost（Docker MySQL）
```

## 4. 项目代码部署

### 4.1 克隆代码

```powershell
# 进入目标目录
cd D:\
mkdir iwork
cd iwork

# 克隆项目
git clone <仓库地址> .

# 或用 ZIP 解压
# Expand-Archive -Path "D:\iwork.zip" -DestinationPath "D:\iwork"
```

### 4.2 创建 .env 文件

```powershell
copy iwork\.env.example iwork\.env
notepad iwork\.env
```

按实际环境修改：

```ini
# Django 配置
DJANGO_SECRET_KEY=<新生成的安全密钥>
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,<服务器IP>,<域名>

# Django 系统数据库（Docker MySQL）
ACCESS_DB_HOST=127.0.0.1
ACCESS_DB_PORT=3306
ACCESS_DB_NAME=iwork_system
ACCESS_DB_USER=iwork_admin
ACCESS_DB_PASSWORD=<应用数据库密码>

# 远程业务数据库（不变）
IWORK_DB_HOST=192.168.3.15
IWORK_DB_PORT=3306
IWORK_DB_NAME=payroll
IWORK_DB_USER=iwork_readonly
IWORK_DB_PASSWORD=<远程库只读密码>

# 本地业务数据库（Docker MySQL）
LOCAL_DB_HOST=127.0.0.1
LOCAL_DB_PORT=3306
LOCAL_DB_NAME=iwork_local
LOCAL_DB_USER=iwork_admin
LOCAL_DB_PASSWORD=<与 ACCESS_DB_PASSWORD 相同>
```

### 4.3 创建 mysql-init 初始化脚本

新建文件 `mysql-init/01-create-databases.sql`：

```sql
CREATE DATABASE IF NOT EXISTS iwork_system
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE DATABASE IF NOT EXISTS iwork_local
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'iwork_admin'@'%'
  IDENTIFIED BY '<应用数据库密码>';

GRANT ALL PRIVILEGES ON iwork_system.* TO 'iwork_admin'@'%';
GRANT ALL PRIVILEGES ON iwork_local.* TO 'iwork_admin'@'%';
FLUSH PRIVILEGES;
```

## 7. 首次部署执行

### 7.1 运行部署脚本

```powershell
# 在项目根目录执行
.\deploy.ps1
```

脚本会自动完成：

1. 环境检查（Docker、Python）
2. 确认 Docker 中间件已启动
3. 创建 Python 虚拟环境
4. 安装 pip 依赖
5. 执行 Django migrate（系统表）
6. 收集静态文件
7. 创建管理员账户（交互式）
8. 注册 Windows 服务
9. 启动所有服务

### 7.2 创建管理员账户

如果首次部署后没有管理员账户，需要手动创建：

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

按提示输入用户名、邮箱、密码。

### 7.3 验证服务状态

```powershell
.\deploy.ps1 -Status
```

期望输出：

```
Docker 容器:  DKT_mysql Up, DKT_redis Up, DKT_iwork_redis Up, DKT_iwork Up
Windows 服务: iwork-uvicorn Running, iwork-celery-worker Running, iwork-celery-beat Running
```

## 8. Nginx 配置

### 8.1 安装配置

将项目中的 `iwork.conf` 复制到 Nginx 配置目录：

```powershell
copy iwork.conf <nginx安装目录>\conf\conf.d\iwork.conf
```

### 8.2 修改配置中的值

编辑 `iwork.conf`，替换以下占位符：

| 占位符 | 替换为 |
|--------|--------|
| `your-domain.com` | 实际服务器域名或 IP |
| `D:/iwork/staticfiles/` | 实际项目路径下的 staticfiles 目录 |

### 8.3 重载 Nginx

```powershell
nginx -s reload
```

### 8.4 Portal 集成配置（auth_request）

当 iwork 部署在 DKT Portal 下时，Nginx 通过 auth_request 统一认证：

```nginx
# 位于 DTD_nginx/docker/nginx-keycloak/site-confs/apps/iwork.conf
# 由 Portal 的 generate_nginx_config 管理命令自动生成

# 认证子请求（oauth2-proxy 验证 OIDC session）
auth_request /oauth2/auth;

# 将认证通过后的用户信息注入 header
auth_request_set $user  $upstream_http_x_auth_request_user;
auth_request_set $email $upstream_http_x_auth_request_email;
proxy_set_header Remote-User $user;
proxy_set_header Remote-Email $email;

# SSE 端点需要关闭缓冲
location /iwork/api/dashboard/stream/ {
    proxy_pass http://iwork:8000/api/dashboard/stream/;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 3600s;
    proxy_set_header Connection '';
    proxy_http_version 1.1;
}

# 通用代理
location /iwork/ {
    proxy_pass http://iwork:8000/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

### 8.5 接口路由表

| Nginx 路径 | 上游 | 说明 |
|------------|------|------|
| `/static/*` | 本地文件 | Nginx 直接返回，不代理 |
| `/api/dashboard/stream/` | Uvicorn :8000 | SSE 实时推送（proxy_buffering off） |
| `/*` | Uvicorn :8000 | 通用 HTTP 代理 |

## 11. 故障排查

### 11.1 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| Uvicorn 服务启动失败 | 端口 8000 被占用 | `netstat -ano \| findstr 8000` 查看占用进程 |
| Celery Worker 无法启动 | Redis 未就绪 | 确认 `docker ps --filter name=DKT_iwork_redis` 中 Redis 为 Up |
| API 返回空数据 | 远程库连接失败 | `Test-NetConnection 192.168.3.15 -Port 3306` |
| SSE 连接失败 | 后端未启动或 Nginx 未代理 | 检查 Uvicorn 是否监听 8000 端口，确认 Nginx 代理 `/api/` 路径 |
| 看板无实时更新 | Celery Beat 未运行 | `Get-Service iwork-celery-beat` |
| 静态文件 404 | collectstatic 未执行 | `python manage.py collectstatic --noinput` |
| 数据库连接拒绝 | MySQL 容器未启动 | `docker ps --filter name=DKT_mysql` 确认状态 |

### 11.2 查看错误详情

```powershell
# Windows 事件日志
Get-EventLog -LogName Application -Source "iwork-uvicorn" -Newest 10

# 各组件错误日志
Get-Content logs\daphne_stderr.log -Tail 20
Get-Content logs\celery_worker_stderr.log -Tail 20
Get-Content logs\celery_beat_stderr.log -Tail 20

# Django 配置检查
.\.venv\Scripts\python.exe manage.py check --deploy
```

### 11.3 完全重装

如需完全重新部署：

```powershell
# 1. 卸载服务
.\uninstall_services.ps1

# 2. 删除 Docker 容器和卷（这会丢失数据！）
docker compose down -v

# 3. 删除虚拟环境
Remove-Item -Recurse -Force .venv

# 4. 重新部署
.\deploy.ps1

# 5. 重新导入数据库
# 按第 6 节步骤操作
```
