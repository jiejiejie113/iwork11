# 历史生产详情与本地持久化

## 范围

- 历史看板增加进入所选日期生产详情的入口。
- 生产详情支持从 URL 读取日期，并在 Flow、工序、产品视图间保留日期。
- 历史日期自动使用本地只读快照，关闭自动刷新和目标编辑。
- 历史页不再提供本地/远程切换和手动同步；快照缺失时由前端自动请求后端构建并重试。
- 历史生产详情不显示实时“最后更新”，目标产量按日期、员工和本厂款号从本地目标表读取。
- 新增按小时聚合的历史事实表、工序产品元数据快照和同步状态表。

## 数据来源

今日数据仍由 Celery 预计算到 Redis。历史快照从远程 `pytckreg3` 只读聚合，
并在同步时冻结 `pywrkstp` 的工序描述和标准工时，以及 `production_orders` 的产品映射。

## 同步

单日回填：

```powershell
docker exec DKT_iwork python manage.py snapshot_history --date 2026-07-15
```

日期范围回填：

```powershell
docker exec DKT_iwork python manage.py snapshot_history `
  --start 2026-07-01 --end 2026-07-15 --continue-on-error
```

Celery Beat 每天上海时间 03:00，即曼谷时间 02:00，自动重建最近三个历史日期。

## 完整性

每次发布校验：

- 聚合行中的源记录数总和等于快照源记录数。
- 聚合行中的产量总和等于快照源总产量。
- 事实表和元数据在同一数据库事务中替换。
- 发布状态仅在全部写入成功后切换为 `success`。

历史员工效率暂不推算，页面继续显示 `--`；后续需先确定班次结束时间和特殊休息日规则。
