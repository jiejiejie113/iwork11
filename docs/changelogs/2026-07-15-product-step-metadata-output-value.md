## 变更概览

本轮修改集中在“生产详情 → 按产品名称”，把工序描述、标准工时和产值统一建立在
`(WrkOrder, StepNo)` 组合键上，并补齐树表与图表展示。

| 改造项 | 最终规则 |
|--------|----------|
| 工序描述来源 | 从 `Pywrkstp.Description` 读取，不再映射或查询 `Pydefstp.Description` |
| 标准工时来源 | 从同一条 `Pywrkstp` 记录读取 `StepTime` |
| 批量查询 | 按完整 WrkOrder 列表一次读取 Description 和 StepTime，避免逐行查询 |
| 产值 | `output_value = qty × step_time`；工时缺失返回 `null`，工时为 0 返回 0 |
| 缓存 | 产品概览最终使用 `stats:detail:product_overview:v4`，隔离旧结构与旧语义 |

## 模型与接口

- `Pydefstp` 只映射 `StepNo`，删除 description 模型字段。
- `Pywrkstp` 映射可空的 `Description`（`char(120)`），与 StepTime 共用
  `CompositePrimaryKey('WrkOrder', 'StepNo')`。
- 产品概览工序节点新增 `description`、`step_time`、`output_value`，实时和本地历史
  模式保持相同响应结构。
- 本地历史模式无法读取远程 Pywrkstp 时降级为空描述、空工时和空产值，不阻断产量数据。

## 树表展示

树表最终列结构为：

```text
维度 | 工序描述（条件显示） | 产量 | 标准工时（条件显示） | 产值 | 信息
```

- “工序描述”“标准工时”仅在激活区同时包含“本厂款号”和“工序号”时出现。
- 路径首次确定完整组合键的行显示描述和工时；父级汇总行和后续生产线行显示 `--`。
- “产值”列始终显示，上层节点汇总全部子记录产值；存在缺失工时时显示 `--`。
- 工序名称保持为纯编号（如“工序15”），描述不再拼接到维度名称或信息列。
- 表格使用动态 Grid 列宽，窄窗口允许横向滚动，避免新增字段被截断。

## 图表切换

- 产品图表右上角增加“产量 / 产值”分段按钮，默认选择“产量”。
- 产量模式使用 qty 构建柱状图并按产量降序排列。
- 产值模式使用 output_value 构建柱状图并按产值降序排列。
- 切换时同步更新标题、数据集名称、平均线和纵轴名称，不改变树表层级顺序。

## Flow 员工明细与效率

- Flow 员工查询沿用 `(WrkOrder, StepNo)` 组合键，一次批量读取
  `Pywrkstp.Description` 和 `Pywrkstp.StepTime`。
- 员工工序节点新增 `description`、`step_time`、`output_value`，员工节点新增汇总
  `output_value`；任一工序缺少标准工时时，员工汇总产值为 `null`。
- Flow 响应新增 `work_minutes` 和 `employee_efficiency`。员工效率计算公式为
  `员工总产值 / 有效上班分钟 * 100%`，不会随款号或工序筛选改变。
- 有效上班分钟使用 UTC+7：07:00 起算，11:00-12:00 固定为 240 分钟，12:00
  后扣除一小时午休；历史日期、上班前和分钟数为 0 时效率为空。
- Flow 接口的“今日”判断和生产详情默认日期统一使用 `Asia/Bangkok`，避免服务器
  UTC 日期在当地凌晨错误指向前一天。
- Flow 明细缓存升级为 `stats:detail:flow:v2:<flow_name>`。缓存只保存工序元数据和
  产值快照，上班分钟与员工效率在每次请求时注入。
- Flow 展开表按“员工 + 本厂款号 + 工序”逐行展示工序描述、标准工时、产量和
  产值；收起表只展示员工级汇总。
- 旧“效率”指标明确改名为“目标达成率”，新增独立“员工效率”列；顶部误标为
  “产值”的目标员工产量修正为“已设目标产量”。
